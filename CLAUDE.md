# Neuroscaping: notes for Claude

Static site, no build step, no dependencies. Open `index.html` through any static server (`node scripts/serve.mjs`).

## Where things live
- `data/genesis.csv`: card table (source of truth for names, types, costs, text).
- `data/mainframes.json`: mainframe lead-ins and synergy tiers (supersedes the CSV text for IDs 235-254).
- `data/abilities_raw.txt`: printed ability names, RAM costs and run icons (read from card images; fan sites omit them). Edit this, not the generated file. Wording rule: a cost of "2 RAM" with the run icon means *run 2 RAM and run (rotate) this character*; say it that way (`src/lib/abilities.js`), never "2 RAM + run" or "upgrade". UPGRADE is only an ability name.
- `src/data/cards.js`: GENERATED by `node scripts/build-data.mjs`. Never edit by hand.
- `data/my_tags.json`: OPTIONAL custom tags the owner's Claude can pre-fill and commit for the playgroup. Shape `{"tags":[{"id","name","color?"}],"cards":{"<cardId>":["<tagId>"]}}` (colour is one of the muted hexes in `TAG_COLORS`, `src/lib/tags.js`). Loaded at boot; a missing or broken file is ignored. A person's local edits (localStorage) layer on top: tags by id, and a locally edited card's list replaces the repo list for that card. Repo tags cannot be deleted in the UI, only here.
- `src/lib/config.js`: factions, tags, subtypes, what counts as "persistent" for synergy, deck limits, rules summary.
- `src/lib/`: pure logic (deck rules, synergy, roles and suggestions, name search, share). Covered by `npm test`.
  - `roles.js`: role classification from rules text, `suggestForMainframe`, `suggestForDeck`.
  - `search.js`: fuzzy name search and the "3 admin" quick-add parser.
  - `graph.js`: deck synergy graph (`deckGraph`, `viewGraph` strength filter, `partnersOf`, deterministic `layoutGraph`). Weights: name 3, tag 1.5, faction 1, subtype 1; strengths Named >=3, Strong >=2 (default), All >=1.
  - `tags.js`: pure tag layer logic (`normalizeTags`, `mergeLayers`, `groupByTag`, `deckTagBoost`). `life.js`: pure life counter state (`newLife`, `adjust`, `setPlayers`, `resetLife`, `normalizeLife`; Mainframe and Bioframe health, both 20, 2-4 players). `backup.js`: `buildBackup`/`parseBackup`/`mergeBackup` (never overwrites; same id with different content comes in as "(imported)").
  - `odds.js`: hypergeometric odds, `cardsSeen`, sample hand (`newGame`, `mulligan`, `drawTurn`). Assumes every draw comes from the cyberdeck.
  - `cardimg.js`: image URLs (`cardImageUrl(card, 'primary'|'fallback')`), alt text (`cardAlt`, full rules text), the per-session "primary failed" flag and source order. Pure; tested.
  - `filters.js`: card-browser filters <-> URL query, plus the pure filter logic: `matchesFilters` (OR within a group, AND between), `facetCounts` (option counts ignoring the option's own group), `activeChips`, and the RAM range (`F.ram = {min, max}`, `null` = open; `decodeRange`/`encodeRange`/`normalizeRange`/`rangeSummary`/`inRamRange`). URL: `ram=1-3`, `2-`, `-3`; the old list form `ram=1,2,5` decodes to min..max. A max of 8 means no max. Mainframes (no RAM cost) are excluded only when a range is set. `abilities.js`: ability cost wording (`costPhrase`).
- `src/main.js`: boot, hash router, top bar. `src/router.js`: route parsing. `src/store.js`: decks in localStorage (`neuroscape-deck-lab:v1`, `{decks, activeId}`). `src/tagstore.js`: the tag layers (`neuroscape-deck-lab:tags:v1`, same shape as `data/my_tags.json`). Small prefs live in `neuroscape-deck-lab:prefs:v1` (keys: `preferTags`, `cardsView` = `images`|`list`, `deckView` = `list`|`visual`, `lifeAwake`). The life counter saves to `neuroscape-deck-lab:life:v1`. sessionStorage `neuroscape-deck-lab:img-primary-failed` remembers that the primary image host failed.
- `src/views/`: one module per page (`home.js` also holds the mainframe list, `mainframe.js`, `deck.js` (Cards tab, hosts the other tabs), `synergy.js` (map and list), `playtest.js` (odds and sample hand), `cards.js` (filter dropdowns, chips, phone sheet), `detail.js` = card drawer incl. tag editing, `life.js` = phone life counter that holds the screen awake via `src/ui/wakelock.js`). Each `mount*` returns `{refresh, destroy}`.
- `src/ui/`: shared pieces (`cardimg.js` card image markup + error chain + lightbox + `keepImages`, `tiles.js` image tile with x N badge and stepper bar, `card.js` notched card frame and chevron banner (now mostly the text-card fallback and ability banners), `parts.js` mainframe meter and tiles, `glyphs.js` faction icons, `combo.js` combobox, `dialogs.js` (incl. My data: tags and backup), `tags.js` tag chips, `dom.js`).
- `src/style.css`: all styling, dark only. Sizes come from tokens at the top of `:root` (`--sp-*` spacing, `--t-*` body type, `--d-*` display type, `--ctl*` control heights, `--cost`). Use them; do not add raw px for padding, gaps, font sizes or control heights. The coarse-pointer / phone block raises `--ctl` to 44px. Design rationale and the scale in `docs/design.md`; screenshots in `docs/screenshots/` (`-placeholder` = generated stand-in images).
- `decks/*.txt`: saved deck lists in the app's text format. `node scripts/check-deck.mjs decks/<file>.txt` validates one.

## Card images
- Shown wherever a card is shown to a person. Hotlinked, never committed (copyright). Primary `https://storage.googleapis.com/spicerack_media/cards/neuroscape/GEN-<id>.webp`, fallback `https://static.playset.pro/neuroscape/cards/en/GEN-<id>.webp`, then a built-in text card (notched frame with name, cost, rules text). 535x750 webp, 5:7.
- `<id>` = card `id` in `src/data/cards.js`: 1..254 and 256 map directly. 255 is Basic RAM (not in the dataset). Unknown ids 404.
- Build images only with `cardImageHtml(card, {size})` / `cardImage` (`src/ui/cardimg.js`): fixed 5:7 box, lazy, full-text alt. A delegated capture-phase `error`/`load` listener runs the chain, so images work inside any `innerHTML` template. After the first primary failure the session starts at the fallback and not-yet-loaded lazy images are switched too.
- Real images get rounded corners and a faction ring on hover/focus, never the notched frame. Repaints of a view should go through `keepImages(root, fn)` so pictures do not blink.
- Rules text stays in: alt text, the drawer's collapsed "Card text", the browser's List mode, search, Copy for AI.
- To check layout offline: serve placeholder webps for the two hosts with Playwright `page.route`.

## Routes (hash)
`#/decks` (home), `#/deck/<id>` (tabs: `#/deck/<id>/synergy`, `#/deck/<id>/playtest`), `#/mainframes`, `#/mainframe/<id>`, `#/cards` (filters live in the query, e.g. `#/cards?fac=Hacker&type=Program&my=ramp`; see `src/lib/filters.js`), `#/card/<id>` (drawer over the previous page), `#/life` (life counter). Old share links `#d=<base64>` still open as a new deck.

## Working on decks with the owner
1. Read the deck file and the card text for every card in it (from `src/data/cards.js`).
2. Judge synergy from rules text, not only from the automatic links in the app (those only show which cards name each other).
3. Check legality with `scripts/check-deck.mjs`.
4. Save new versions as new files in `decks/` (e.g. `hacker-v2.txt`). The playgroup can paste them into the app's Import.

## Known assumptions (confirm with the owner)
- "Persistent" cards (count toward faction synergy): Characters, Gear, and Programs of subtype Protocol / Environment / Datashard.
- Null is treated as a faction. Mainframes themselves give no synergy.
- The RAM deck (a separate deck of exactly 25 RAM cards) is not modelled; it is not part of the cyberdeck and RAM is not drawn from the cyberdeck.
- Names cut off on card images are stored with a trailing "…" in `abilities_raw.txt` and could be completed.
